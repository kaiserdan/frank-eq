# Lineage and negative evidence

Frank-EQ is a synthesis of the Frank/USAE research program, but it does not treat historical branches as one confirmatory experiment.

## Reused lessons

### Shared geometry is real but receiver asymmetric

Earlier canonical and structured transport systems produced substantial cross-model predictability, including canonical latent R2 around 0.8 and strict pairwise values around 0.5. Receiver-level results varied from near one to negative. Frank-EQ therefore permits complete model-local charts and never interprets an average geometry metric as universality.

### Better latent metrics can worsen execution

Source-conditioned canonical variants and legal-realizer audits showed that improved latent reconstruction need not improve target token ordering. Frank-EQ defines its public state in future-behavior units and removes target hidden reconstruction from the primary path.

### Predictable trajectories need not continue

Bary-style predictable subspaces reached high held-out reconstruction and phase/velocity metrics while true continuation remained negative. Frank-EQ may use multi-layer captures but does not claim learned dynamics unless held-out future branches pass.

### Explicit semantics omit predictive state

ExplainFrank found strong coarse semantic and predictive readouts, while exact-token and executable claims remained blocked. Frank-EQ separates grounded coordinates from an operational residual and requires a facts-only ablation.

### Average utility is not specificity or safety

Frank-Sol found strong average causal readout gains with unresolved control geometry and harm-tail behavior. Frank-EQ includes matched wrong worlds, uncertainty, grouped inference, and fail-closed gates from the first stage.

### Oracle receiver utility is not sender compilation

CTSI showed that a sufficient structured packet can causally improve frozen receivers, while independently trained source compilers failed invariant RULE/renderer qualification despite high fact recovery. Frank-EQ focuses first on discovering the operation-complete source state and tests held-sender establishment before receiver execution.

## What is not imported

- old checkpoints or selected hyperparameters;
- target-private synthesis;
- pair-specific primary translators;
- post-outcome gates;
- incomplete or smoke-only outcomes;
- claims that state R2 implies receiver execution.
